# טופס למידע — מטפסי התחייבות לאקסל

דמו להאקתון AI קוד פתוח, אתגר המעבדה המרכזית לנגיפים.

**מה המערכת עושה:** גוררים טפסי התחייבות סרוקים — כמה שרוצים, תמונות ו/או PDF →
מודל אחד חזק (Claude Opus 5.5, בחשיבה עמוקה) קורא כל טופס לבד →
טבלה בעברית עם סימון כתום לכל מה שדורש בדיקה → תיקון במקום → הורדת Excel.

## הרצה

להכנה לענן ב־Vercel עם DB ואחסון קבועים ב־Supabase, ראו
[הסבר הפריסה ו־Docker](CLOUD_DEPLOYMENT.md).
מצב ענן מופעל במפורש עם `CLOUD_MODE=1`; ההוראות שלהלן מיועדות להרצה המקומית.

```powershell
uv sync        # פעם אחת
uv run serve   # נפתח אוטומטית בדפדפן ב-http://127.0.0.1:8000
```

**מומלץ: Tesseract**, לזיהוי דף שנסרק על הצד או הפוך, וסיבוב שלו לפני הקריאה. הוא
מקומי וחינמי, ומשמש רק לכיוון הדף. בלעדיו המערכת עובדת, אבל דף מסובב נקרא מסובב,
והתקריבים עלולים לצאת במקום הלא נכון.
- Windows: `winget install UB-Mannheim.TesseractOCR`, או המתקין מ-
  github.com/UB-Mannheim/tesseract.
- Linux / Docker: `apt-get install tesseract-ocr`.
- נמצא אוטומטית ב-PATH או ב-`C:\Program Files\Tesseract-OCR`. אחרת: `TESSERACT_CMD=` ב-`.env`.

### המסך (React)

הבנייה (`backend/app/web/dist`) שמורה ב-Git, ולכן `uv run serve` מספיק — אין צורך ב-Node כדי להריץ.
רק אחרי שינוי בקוד המסך:

```powershell
cd frontend
npm ci          # פעם אחת
npm run build   # בדיקת טיפוסים (tsc) + בנייה אל backend/app/web/dist
```

- **איך המראה נשאר זהה:** הרכיבים של MUI (כפתורים, חלונות) נכנסים לשכבת CSS נמוכה (`@layer mui`), והעיצוב
  הקיים (`app.css`) גובר תמיד. MUI מוסיף התנהגות: פוקוס שנשאר בתוך חלון, Esc, נגישות, ימין-לשמאל.
- **נבדק מול המסך הקודם** בדפדפן אמיתי, בחינם: 11 מסכים וחלונות זהים לפיקסל (כולל מצב כהה), וכל המסלולים
  נותנים תוצאה זהה — העלאה, אישור עד הקונפטי, ייצוא, רשומות, ממתינים, ניווט אחורה/קדימה, טופס מהמערכת,
  חיבור חצאים, פיצול, עזרה ותשובת הממונה.

## מה צריך ב-`.env`

```
ANTHROPIC_API_KEY=...
```

זה הכול. החשבון צריך יתרת קרדיט פעילה ב-console.anthropic.com; בלעדיה הקריאה נכשלת
והמסך מציג זאת בהודעה ברורה. שאר ההגדרות ב-[.env.example](.env.example) אופציונליות.

**מהירות (מומלץ):** `MAX_PARALLEL_CALLS=10` ב-`.env` — כמה טפסים נקראים בבת אחת (ברירת המחדל: 6).
זה משנה רק את הקצב, **לא את המחיר לטופס**. 10 הוא צעד זהיר: מגבלת הקצב של החשבון לא ידועה, ואם
מופיעות שגיאות "rate limit" — להוריד. הכנת העמודים (סיבוב, יישור) רצה 8 עמודים במקביל, והקריאה
מתחילה ברגע שהעמוד הראשון מוכן — בלי לחכות לשאר. (בענן: ההכנה מקבילה, והקריאה מתחילה אחרי שכל העמודים מוכנים — שמירת המצב ל-DB רצה מתהליך אחד.)

## כללים שהמערכת שומרת

- **מספרים הם מחרוזות.** אפסים מובילים נשמרים, גם בתא ב-Excel.
- **שדה שלא נמצא נשאר ריק ומסומן כתום** ("לא קיים בטופס"). לא מנחשים.
- **כתום = צריך בדיקה**: המודל לא בטוח, או שבדיקה אוטומטית נכשלה (ת"ז, תאריך, גורם שולח,
  אורך חריג, אותו מספר בשני שדות). ירוק = אדם תיקן או אישר. תא רגיל אינו טענת נכונות.
- **תאריך קבלה בלבד** מחותמת "התקבל" או בכתב יד מתחת למספר המרכזי — לא הפקה, לא לידה, לא תוקף.
- **גורם שולח** נבחר מרשימה סגורה; שם שאינו ברשימה נשאר כפי שנקרא ומסומן כתום.
- ערכים מרובים נשמרים כולם. באקסל: **שורה לכל מספר התחייבות**; מספרים מרכזיים נשארים יחד.
- ערך שמתחיל ב-`=`, `+`, `-` או `@` נכתב כטקסט ולא ירוץ כנוסחה ב-Excel.
- תוכן המסמך הוא מידע, לא הוראה למודל.

## מגבלות ידועות

- **טופס נשמר ב-SQLite רק אחרי "אישור הטופס"** (`work/forms.db`). הוא נשמר פעם אחת: אישור חוזר של אותו
  עמוד מעדכן את השורות שלו. טבלת `approved_rows` בנויה כמו האקסל, שורה לכל מספר התחייבות. הלשונית
  **"רשומות במערכת"**:
  - טוענת רק את מה שאושר היום, או אתמול, 7 ימים, החודש או טווח אחר. את כל המאגר היא לא טוענת אף פעם.
  - מאפשרת חיפוש, סינון לפי גורם שולח ולפי תאריך קבלת הדגימה, וייצוא ל-Excel, CSV או JSON של מה שמסונן.
  - פתיחה של טופס מחזירה אותו למסך הבדיקה בלי לקרוא אותו שוב.
  - מספר התחייבות שקיים בטופס מאושר אחר מסומן "ייתכן כפול", ולא נמחק ולא מאוחד.
  - מחיקה מוחקת את הטופס ואת התמונות שלו.
  - טפסים שאושרו לפני 20/10/2026 מוצגים ומיוצאים, אבל אי אפשר לפתוח אותם.
  - **טופס שכבר אושר ומועלה שוב** חוזר עם הערכים מהמערכת: כל השדות ירוקים והטופס מאושר, עם הערה "הנתונים
    מהמערכת" ([backend/app/known.py](backend/app/known.py)).
    - אותו קובץ בדיוק מזוהה לפי התמונה, בלי מודל ובלי עלות.
    - קובץ אחר של אותו טופס (מספר התחייבות זהה, ות"ז זהה או חסרה) נקרא קודם במודל.
    - שינוי שדה דורש אישור בחלון, ואחריו "אישור הטופס" מחדש.
    - האישור האחרון דורס את הגרסה הקודמת, כך שנשארת רשומה אחת לכל טופס.
  - קבצי הזהב ב-`evaluation/gold` לא נמחקים.
  הכול מקומי ומחוץ ל-Git, כי יש בו פרטי מטופל. התשובות של המודל נשמרות ב-`work/read_cache`.
- **ממתינים לאישור:** טפסים שנקראו ועוד לא אושרו נשמרים בטבלה נפרדת, שורה אחת לכל טופס, **רק כשצריך**:
  - הדף נסגר או מוסתר (סגירת הדפדפן, כיבוי המחשב).
  - השרת נסגר בצורה מסודרת.
  - מתחילים העלאה חדשה בלי לסיים את הקודמת.

  ב"רשומות במערכת", תחת "ממתינים לאישור", לחיצה פותחת את הטופס לבדיקה. אחרי "אישור הטופס" הוא עובר
  למאושרים. נפילת חשמל פתאומית עלולה לאבד תיקונים מאז השמירה האחרונה.
- **עמוד = טופס**, עם חריג אחד: טופס חתוך לשני חלקים (חצי עליון וחצי תחתון), בתמונות או בעמודי PDF,
  מחובר אוטומטית בלי קריאה נוספת ([backend/app/halves.py](backend/app/halves.py)). ההחלטה לפי התוכן:
  - לחלק התחתון אין פרטי מטופל.
  - לעליון חסר מה שהתחתון מביא.
  - הגורם השולח זהה.

  עמוד PDF מתחבר רק לעמוד הצמוד לו, גם בין קבצים. עמוד בלי שום נתון מקבל הצעה לחיבור ידני. הטופס המחובר כתום
  עד בדיקה. יש כפתור "הפרד", ואחריו "חבר בחזרה", וגם "חבר עם חלק אחר" לחיבור ידני של חלקים
  שלא חוברו אוטומטית. חיבור ידני אפשרי רק לחלקים חתוכים: תמונות שחסרים בהן פרטי המטופל או צד
  ההתחייבות. הכול בחינם.
- **שני טפסים בעמוד אחד** ([backend/app/twoforms.py](backend/app/twoforms.py)):
  - **המזכירה מחליטה.** אין פיצול אוטומטי. בסרגל הטופס יש כפתור "✂ פיצול לשני טפסים", והיא בוחרת "אחד
    מעל השני" או "זה לצד זה".
  - **בחינם, בלי קריאה נוספת למודל.** העמוד נחתך, וכל ערך שכבר נקרא עובר לחלק שבו נמצאת התיבה שלו. ערך
    בלי מיקום, או ערך שחוצה את קו החיתוך, לא מנוחש: השדה נשאר ריק. כל השדות בשני החלקים כתומים, לבדיקה.
  - בחלק שפוצל, אותו כפתור הופך ל"↺ בטל פיצול" ומחזיר את העמוד, בחינם.
  - טופס רב־עמודי (לא חצאים) עדיין לא נתמך.
- **30 טפסים לגרירה** כברירת מחדל (`MAX_PAGES_PER_BATCH`), ותקרת תקציב של $10 להעלאה.
- **כללים מחייבים** ([backend/app/rules.py](backend/app/rules.py)), שהשרת אוכף ולא רק המסך:
  - ת"ז אחת לטופס, ספרות בלבד, עם ספרת ביקורת תקינה.
  - תאריך אמיתי בפורמט DD/MM/YYYY ולא בעתיד.
  - שם באותיות בלבד. שם של כמה מילים ("ישראל מאיר") הוא ערך אחד ומותר.
  - מספר מרכזי והתחייבות: כל תו, ובלבד שיש בו לפחות ספרה אחת. אין פורמט רשמי, ולכן לא מגבילים לפי הדוגמאות.
  - כשאין ערך, האפשרות היחידה היא שדה ריק ("חסר"). "לא ברור" ו"לא מובן" נדחים.
  - ערך שאינו עומד בכלל לא נשמר, אין לו ✓, והטופס לא מאושר.
  - טופס שאושר לפני הכללים ואינו עומד בהם מסומן "לא עומד בכללים". הוא לא נמחק ולא משתנה.
  - גורם שולח שאינו ברשימה נשאר כתום ואפשר לאשר אותו, כי בדוגמאות יש גורמים אמיתיים שאינם ברשימה (צה"ל, משרד
    הביטחון).
- **🙋 עזרה** — כשהמזכירה מתלבטת בשדה כתום, היא שולחת לממונה בקשת עזרה בוואטסאפ, במייל או כקישור מועתק:
  - כותבים בחלון למי לשלוח: כתובת מייל או מספר נייד, והמערכת זוכרת את האחרונים.
  - Gmail, Outlook או וואטסאפ נפתחים בלשונית חדשה עם הודעה מוכנה, והנמען כבר ממולא. נשאר רק ללחוץ "שליחה".
  - המערכת עצמה לא שולחת מיילים מהשרת.
  - בהודעה עצמה **אין פרטי מטופל**, רק קישור עם מפתח אקראי.
  - הקישור מציג רק את התקריב והערכים של השדה הזה, והממונה עונה בו.
  - עד שמגיעה תשובה השדה והטופס לא מאושרים. התשובה מופיעה על המסך לבד, וההחלטה נשארת של המזכירה.
  - כל שאלה ותשובה נשמרות ב-`help_requests` ולא נמחקות.
  - ההודעה מפרטת את השדה ואת השאלה, וחתומה "מערכת קליטת טפסי התחייבות · המעבדה המרכזית לנגיפים".
  - ההודעה היא טקסט בלבד: קישורי Gmail, Outlook ווואטסאפ לא מעבירים תמונה או עיצוב.
  - **אבטחת הקישור:**
    - מפתח אקראי של 144 ביט;
    - **תוקף של 48 שעות**;
    - אחרי תשובה, ביטול או החלטה של המזכירה, הקישור כבר לא מציג ערכים או תקריב;
    - קישור שפג נשמר בתיעוד, ו"שליחה שוב" יוצרת קישור חדש.
  - מגבלות:
    - **אין עדיין התחברות.** מי שמחזיק בקישור, בתוך 48 השעות, רואה את השדה הזה. בגרסה אמיתית צריך הזדהות, למשל
      בחשבון הממשלתי.
    - על `localhost` הקישור נפתח רק באותו מחשב.
- **"המודל לא סימן ספק" אינו הוכחה.** אין קורא שני; הבדיקות המקומיות והמזכירה הן הבלם.

## מדידה

```powershell
uv run evaluate --saved  # בחינם: הקריאות השמורות מול הטפסים שאושרו → EVALUATION.md
uv run evaluate          # מציג תוכנית ועלות משוערת — לא מוציא כסף
uv run evaluate --yes    # קריאה טרייה של כל הטפסים המאושרים (עולה כסף)
```

הדוח: [EVALUATION.md](EVALUATION.md). סיכום ההגשה: [SUBMISSION.md](SUBMISSION.md).
המדידה תמיד קוראת מהמודל, ולעולם לא את הערכים השמורים במערכת (`use_saved=False`).

## בדיקות

```powershell
uv run pytest -q
```
