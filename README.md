# טופס למידע: מטפסי התחייבות לאקסל

**קליטה, בדיקה וייצוא של טפסי התחייבות סרוקים, למעבדה המרכזית לנגיפים.**

האקתון AI קוד פתוח 2026 · אתגר המעבדה המרכזית לנגיפים, משרד הבריאות

**🌐 האתר החי:** [tofes-demo-noa-2162.vercel.app](https://tofes-demo-noa-2162.vercel.app)
(לטפסי הדוגמה של המארגנים בלבד)

---

## הבעיה

כל יום מגיעות למעבדה דגימות, ועם כל אחת טופס התחייבות: מודפס, סרוק, מצולם או כתוב ביד.
היום מישהי מקלידה את כל הטפסים לאקסל, ידנית.

## הפתרון

1. **גוררים** ערימה של טפסים: PDF סרוק ו/או צילומי טלפון, כמה שרוצים.
2. **המודל קורא** כל טופס ישירות מהתמונה ומחלץ 7 שדות.
3. **כל ספק נצבע בכתום**, עם הסיבה. המזכירה בודקת רק את הכתום, עם תקריב מהטופס המקורי ליד כל שדה.
4. **אדם מאשר**, ורק אז הטופס נשמר במערכת.
5. **ייצוא לאקסל**: שורה לכל מספר התחייבות.

**השדות:** שם פרטי · שם משפחה · תעודת זהות · מספר מרכזי · תאריך קבלת הדגימה · גורם שולח · מספר התחייבות

## העיקרון: אף ערך שגוי לא עובר בשקט

| צבע | משמעות |
|---|---|
| 🟧 כתום | צריך בדיקה: המודל לא בטוח, בדיקה אוטומטית נכשלה, או שהשדה ריק |
| ⬜ רגיל | המודל בטוח והבדיקות עברו. **זו לא טענת נכונות** |
| 🟩 ירוק | אדם בדק ואישר. רק אדם צובע בירוק |

- **לא מנחשים.** שדה שלא נמצא נשאר ריק וכתום. ספרה שלא נקראה מסומנת `?`, ולא מושלמת.
- **מספרים הם טקסט.** אפסים מובילים נשמרים, גם בתא באקסל.
- **כללים בקוד, לא רק במודל:** ספרת ביקורת של ת"ז, תאריך אמיתי ולא בעתיד, רשימה סגורה של גורמים שולחים,
  אותו מספר בשני שדות.
- **תוכן הטופס הוא מידע, לא הוראה למודל.** ערך שמתחיל ב-`=`, `+`, `-` או `@` נכתב באקסל כטקסט ולא ירוץ כנוסחה.

## מה יש במערכת

<details>
<summary><b>קליטה</b>: ערימה של קבצים, טופס אחרי טופס</summary>

- PDF ותמונות יחד, עד 30 טפסים בהעלאה (ניתן לשינוי).
- דף שהגיע על הצד או הפוך מסובב, ודף עקום מיושר. מקומי ובחינם, לפני המודל.
- צילום מסך או תמונה קטנה מוגדלים לפני הקריאה, כדי שהמיקומים יהיו מדויקים.
- כמה טפסים נקראים במקביל, וכל טופס מופיע על המסך ברגע שהוא מוכן.
- דף שכבר נקרא בעבר לא נשלח שוב למודל: התשובה השמורה חוזרת בחינם.

</details>

<details>
<summary><b>בדיקה ואישור</b>: טבלה, אריחים או טופס-טופס</summary>

- תקריב מהטופס המקורי לכל שדה. אפשר לגרור את התקריב ולראות מה מסביב.
- תיקון במקום, "בטל" לכל פעולה, ו"אישור הטופס" בסוף.
- **טופס בשני חצאים** (חלק עליון ותחתון, גם בתוך PDF) מחובר אוטומטית לפי התוכן. אפשר להפריד ולחבר ידנית.
- **שני טפסים בעמוד אחד:** המזכירה מפצלת בכפתור, בחינם ובלי קריאה נוספת. אפשר לבטל.
- **טופס שכבר אושר בעבר** חוזר עם הערכים מהמערכת, רק כשמספר ההתחייבות וגם הת"ז זהים ונקראו במלואם.
  אחרת הוא נקרא רגיל, ומספר ההתחייבות מסומן "כבר קיים במערכת, לבדוק".
- ניווט מלא במקלדת, הגדלת טקסט ומצב כהה.

</details>

<details>
<summary><b>🙋 עזרה מהממונה</b>: שאלה על שדה אחד, בלי פרטי מטופל בהודעה</summary>

- המזכירה שולחת לממונה קישור: במייל ישירות מהאתר, בוואטסאפ, או כקישור מועתק.
- **בהודעה עצמה אין פרטי מטופל**, רק קישור עם מפתח אקראי של 144 ביט, בתוקף 48 שעות.
- הקישור מציג רק את התקריב של השדה הזה. אחרי תשובה או ביטול הוא כבר לא מציג דבר.
- התשובה מופיעה על המסך של המזכירה לבד, וההחלטה נשארת שלה. עד אז השדה לא מאושר.

</details>

<details>
<summary><b>רשומות במערכת</b>: מה שאושר, ומה שממתין</summary>

- רק טפסים שאדם אישר נשמרים. שורה לכל מספר התחייבות.
- טפסים שלא אושרו נשמרים כ"ממתינים לאישור" כשסוגרים את הדפדפן או מתחילים העלאה חדשה.
- חיפוש, סינון לפי תאריך וגורם שולח, סימון "ייתכן כפול", מחיקה, וייצוא ל-Excel, CSV או JSON.

</details>

## תוצאות (נמדד, לא הוערך)

נמדד על 15 טפסי דוגמה שאדם בדק ואישר. הדוח המלא: [EVALUATION.md](EVALUATION.md).

| מדד | תוצאה |
|---|---|
| **שגיאות שקטות** (ערך שגוי שלא סומן בכתום) | **0** |
| ערכים שהמודל הציע ושהיו נכונים, כולל הכתומים | 89% |
| שדות נכונים בלי שום צורך בבדיקה | 28% |
| השדות הקשים ביותר | שמות בכתב יד |

**מגבלות המדידה:** מדגם קטן, מטפסי הדוגמה בלבד, ובגרסת הוראות קודמת. "כתום" אינו הסתברות מכוילת.
אין כאן טענת דיוק מובטח או מוכנות לייצור.

## איך זה בנוי

**העלאה** ← בדיקת סוג הקובץ ← הכנת העמודים (סיבוב, יישור) ← תשובה שמורה, אם הדף כבר נקרא ←
**המודל קורא** ← כללים בקוד ← כתום או רגיל ← **בדיקה ותיקון** ← **אישור אדם** ← שמירה ← **ייצוא לאקסל**

| שכבה | טכנולוגיה |
|---|---|
| מסך | React 18, TypeScript, Vite, MUI 7, ימין-לשמאל, עיצוב gov.il |
| שרת | Python, FastAPI, Pydantic, uv |
| קריאת הטופס | Claude Opus 5.5 (מודל ראייה), דרך חוזה אחד שניתן להחליף |
| נתונים | SQLite במחשב · PostgreSQL ו-Storage פרטי ב-Supabase בענן |
| ענן | Vercel: שרת האתר ועובד רקע לקריאה |
| קבצים | pypdfium2, Pillow, Tesseract (לכיוון הדף בלבד), openpyxl |

**מודל אחר, גם פנימי, בלי לגעת בשאר הקוד:** כל הקריאה עוברת דרך חוזה אחד, `ExtractionProvider`, בקובץ
[providers/base.py](backend/app/providers/base.py). הקובץ [claude_vision.py](backend/app/providers/claude_vision.py)
הוא היחיד שמכיר את ספק המודל.

## הרצה במחשב

```powershell
uv sync
uv run serve
```

`uv sync` פעם אחת. `uv run serve` פותח את המערכת בדפדפן, בכתובת `http://127.0.0.1:8000`.

ב-`.env` צריך רק `ANTHROPIC_API_KEY=...`. שאר ההגדרות אופציונליות ומוסברות ב-[.env.example](.env.example).

**מומלץ: Tesseract**, לסיבוב דף שנסרק על הצד או הפוך. מקומי וחינמי:
`winget install UB-Mannheim.TesseractOCR`. בלעדיו המערכת עובדת, אבל דף מסובב נקרא מסובב.

המסך הבנוי שמור ב-Git, ולכן אין צורך ב-Node כדי להריץ. רק אחרי שינוי בקוד המסך:
`cd frontend`, `npm ci`, `npm run build`.

<details>
<summary><b>הגדרות שימושיות</b></summary>

| הגדרה | ברירת מחדל | מה היא קובעת |
|---|---|---|
| `READER_EFFORT` | `medium` | עומק החשיבה של המודל: `low`, `medium`, `high` |
| `MAX_PARALLEL_CALLS` | `6` | כמה טפסים נקראים בבת אחת. משנה את הקצב, לא את המחיר |
| `MAX_PAGES_PER_BATCH` | `30` | תקרת טפסים להעלאה |
| `MAX_COST_PER_BATCH_USD` | `10` | תקרת עלות להעלאה |
| `BRAND` | `moh` | המראה: `moh` (משרד הבריאות) או `neutral` |
| `BREVO_API_KEY`, `MAIL_FROM` | — | שליחת מייל "🙋 עזרה" ישירות מהאתר, דרך Brevo |
| `HELP_MAIL_ALLOWED` | — | למי מותר לשלוח מייל עזרה. חובה באתר ציבורי |

</details>

**בענן:** Vercel ו-Supabase. ראו [CLOUD_DEPLOYMENT.md](CLOUD_DEPLOYMENT.md) להקמה,
ו-[CLOUD_MAINTENANCE_HE.md](CLOUD_MAINTENANCE_HE.md) לתחזוקה.

## בדיקות ומדידה

| פקודה | מה היא עושה |
|---|---|
| `uv run pytest -q` | מאות בדיקות, בלי רשת ובלי עלות: המודל מדומה |
| `uv run evaluate --saved` | מדידה בחינם: הקריאות השמורות מול טפסים שאדם אישר |
| `uv run evaluate` | מציג תוכנית ועלות משוערת, בלי להוציא כסף |

הבדיקות מכסות, בין השאר: סוג קובץ, סיבוב, אפסים מובילים, תאריכים, ת"ז, רשימה סגורה, שורה לכל התחייבות,
נטרול נוסחאות, חצאי טפסים, טופס שכבר אושר, בקשות עזרה ושליחת מייל, והענן.

## מגבלות ידועות

- **הקורא הוא שירות חיצוני** (Claude API). בדמו נשלחים אליו רק טפסי הדוגמה, שבהם הפרטים האישיים שונו.
  לשימוש אמיתי צריך מודל בתוך רשת המשרד, ומדידה חוזרת על טפסים אמיתיים.
- **אין עדיין הרשאות משתמשים.** אתר הדמו פתוח, וקישור "🙋 עזרה" נפתח בלי התחברות.
- **"המודל לא סימן ספק" אינו הוכחה.** הבדיקות בקוד והמזכירה הן הבלם.
- **טופס רב-עמודי** (שאינו שני חצאים) עוד לא נתמך.
